# AllAnime 播放、匹配与语言刷新走读

日期：2026-09-05。实现位于 `v1` 工作区；保留已有重构改动。

## 结论

截图不是单一的“匹配错了”：对应作品的 AniList ID 为 `178789`，AllAnime ID 为 `qSyzgmuetej3MG4dA`，第三季本身匹配正确。错误发生在随后解析播放地址的 bootstrap 阶段。与此同时，标题匹配、线路状态、播放错误处理和语言列表请求确实还各有问题。

## 播放协议与 StreamBert 对照

- 原实现固定 build `149`，当前公开客户端为 build `162`；签名片段、salt、前缀和拼接顺序同时变化，所以只替换版本号不够。
- [StreamBert 的 AllManga 实现](https://github.com/truelockmc/streambert/blob/main/src/ipc/allmanga.js)仍使用旧 AllAnime 协议。按其源码请求，GET APQ 返回 `PERSISTED_QUERY_NOT_FOUND`，POST fallback 返回 `AA_CRYPTO_MISSING`。它可供借鉴，但不能作为当前可播放的证明。
- 本次以 [MKissa 官网](https://mkissa.to/)和官网实际引用的[公共客户端文件](https://cdn.mkissa.net/all/mk/_app/immutable/chunks/CHU7e2Q8.js)验证正在运行的协议。AllManga 仍提供旧 Nuxt 页面；AllAnime.to 本次访问超时，不据此判断其他网络环境的可用性。

已将易变部分隔离在 `allanime_protocol.rs`：从官网入口发现发布配置，只解释受限常量、算术和字符串表，不运行远程 JavaScript；固定官网/CDN 边界，禁止重定向，限制响应大小和发现时间。缓存遵循有效期及服务器 `switchAt`，遇到旧 build 404 或加密协议错误自动刷新一次。若上游更改协议结构而非发布参数，仍需维护该模块。

目前保留经过验证的 Yt-mp4 直链。该作品其余部分站内来源实际上是 iframe，不把它们冒充 MP4。现有媒体代理支持有请求头要求的分段 MP4，不声称已经支持任意第三方 HLS 的 manifest、segment 和 key 重写。

## 作品与剧集匹配

1. 优先利用双方共有的 AniList ID，同 ID 优先，明确不同 ID 排除；匹配到共同 ID 后停止多余别名查询。
2. 缺少共同 ID 时才使用标题、年份、季度和分部信息。`III / 3rd Season / Season 3` 视为等价，`Part / Cour` 不混为季数，Season 10 不再误判 Season 1。
3. 连载作品的“已经上线集数”不等于目录的“预计总集数”。截图目录共 14 话而来源字幕上线 10 话、配音上线 8 话，是版本可用性信息，不能直接当成错配证据。
4. 自动匹配不覆盖已成功播放的人工选择。手动重新搜索解除目录 ID/年份约束，允许真正纠错；保留稳定的原始别名，不用本地化后的显示标题替代匹配身份。

## 播放状态修复

- 播放源偏好仅在进入该作品时初始化；换集、历史刷新、保存绑定不再夺走手动选择。
- 字幕/配音切换直接生效，重试按稳定线路 ID 保留选择。
- 换集不重新搜索整部作品，过期搜索、剧集及解析响应被丢弃；旧视频资产不能短暂挂到新一集。
- 真正开始播放后才记住作品和线路绑定；观看进度携带作品、集数和来源快照，避免把上一话进度写入下一话。
- 重试解析当前选择，而非清空后重新匹配；媒体报错可正常切入错误界面。
- 补齐 HLS fatal error 和标准 MIME 识别；首次加载 60 秒仍未 ready 时提供可重试错误，避免永久加载。

## 显示语言与缓存

根因不只是缓存：原列表、搜索及日历接口此前没有执行缺失中文标题的补全，《无职转生》第三季在 AniList 本身也缺少中文别名。

- 列表、搜索、日历请求及缓存键均包含显示语言，切换后取消旧请求、使目录缓存失效并重新读取首页列表。
- 设置页显示正在重载、成功或失败状态；保留手动重新载入按钮。语言保存失败会回退选择，列表刷新失败不会撤销已经保存的语言。
- 中文缺失项从匹配的 Bangumi 条目补全：全局 4 并发，单请求 4 秒，整页最多等待 6 秒；相同作品请求合并。成功、无匹配、临时网络失败使用不同缓存期限，避免一次失败永久锁住英文。
- 资料库和继续观看按可见项补全标题，优先复用目录缓存，最多 2 并发，不全量请求历史记录。标题补全使用独立查询键，避免首页离屏取消请求时一并取消播放页的详情加载；Tauri 详情请求不消费无法真正中止传输的 AbortSignal。
- 不把仅含标题的列表对象当作完整中文详情缓存；角色/制作方等专名保持原数据。缺少可信中文简介时不借用其他季度简介，例如当前第三季的 Bangumi 简介为日文，中文模式不误展示成中文。
- 仍可能有上游没有中文名称的作品，回退原名；刷新并不等于机器翻译所有数据。

## 首播等待的实测拆分

同一集一次样本：搜索 553 ms、选集 362 ms、冷协议发现 15.02 s、bootstrap 360 ms、已有配置的解析 549 ms。媒体 1 KiB Range 182 ms，4 MiB Range 1.12 s。视频已经是 fast-start，但 `moov` 长约 1.11 MiB，所以直接把代理块缩到 1 MiB 反而可能拆开元数据。

据此保留 4 MiB 代理上限；官网入口继续重新验证，带内容 hash 的 immutable CDN 文件恢复正常缓存。后续样本协议发现为 2.64 s，且只需一个协议 chunk。CDN 波动明显，不能把全部差异归因于缓存修改，也不承诺固定首播耗时。新增 ignored 延迟诊断测试便于以后按阶段复测。

## UI 与布局

按 Impeccable 的 harden 流程，保持栗梅色、shadcn/ui 和 Tailwind，不做无关的整体重画。

- 播放侧栏以“播放源 → 当前作品 → 剧集”排序；匹配完成后收起长候选列表，必要时再展开搜索。
- 直接呈现可播放集数与字幕/配音版本，不用“已确认”掩盖尚未实际播放的状态。
- 主错误文案给出行动建议，原始技术诊断折叠保留；收起侧栏后内部控件不再进入键盘焦点。
- 保留无可见滚动条的浏览体验，补齐日历/首页的空数据与重试状态，避免无限骨架屏。
- HLS 依赖按需加载，播放页首批脚本从约 759 KB 降到约 169 KB（未压缩构建产物）；独立 HLS 分块约 592 KB，仅相关线路使用时加载。

## 验证记录

- Rust 工作区库测试：53 项通过；需要网络/外部 fixture 的测试默认忽略并单独执行。
- 前端回归：8 项通过，其中 5 项覆盖选择逻辑；另 3 项使用真实 QueryClient/QueryObserver 重现导航 CancelledError，并验证独立标题查询不再取消详情加载。
- 在线测试：芙莉莲第 1 话、无职第三季第 1 话，各 sub/dub 四路均得到 HTTP 206、正确 Content-Range、1024 字节与 MP4 `ftyp`。
- 旧 build149 缓存注入测试可自动恢复；真实媒体经过 Kuriume 代理的 Range 测试通过。
- 中文搜索/详情两项在线测试通过，包含无职第三季的中文标题和芙莉莲中文简介。
- 独立 macOS QA 应用中，实际看到无职第三季第 1 话视频、23:40 时长及持续前进的进度；切换配音后持续播放，随后第 2 话成功播放且保留配音版本。
- QA 应用 English 切到中文后显示重载中和成功提示；返回首页时 Hero、作品列表与继续观看记录使用中文标题，未重启应用。
- 最后通过干净重启再次从继续观看进入第 2 话，确认不再出现 CancelledError，恢复配音及 16 秒观看进度，并实际播放至 36 秒。
- TypeScript、构建、工作区 Clippy `-D warnings` 通过；Impeccable 对本轮界面文件的合并静态检测返回空结果。

测试表明当前链路可用，不代表所有动漫、网络环境及未来站点版本均有同等可用性。真实播放还受上游媒体质量、线路覆盖和 CDN 速度影响。
